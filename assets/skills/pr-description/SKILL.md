# Skill: pr-description

## Когда использовать
Когда разработчик просит подготовить описание Pull Request / Merge Request или
«описать изменения для ревью».

## Что собрать перед написанием
1. Диапазон изменений относительно базовой ветки:
   `git diff <base>...HEAD` и `git log <base>..HEAD --oneline`.
2. Номер тикета из имени ветки.
3. Затронутые области/пакеты.

## Шаблон описания
```markdown
## Что и зачем
<1–3 предложения: суть изменения и мотивация. Ссылка на тикет: [ABC-123]>

## Изменения
- <ключевое изменение 1>
- <ключевое изменение 2>

## Как тестировать
- [ ] <шаг проверки 1>
- [ ] <шаг проверки 2>

## Скриншоты / видео
<для UI-изменений — до/после; иначе «н/д»>

## Риски и обратная совместимость
<breaking changes, миграции, фиче-флаги или «нет»>
```

## Правила
- Пиши по-русски, кратко и по делу; фокус на «зачем», а не пересказ диффа.
- Для UI-изменений раздел со скриншотами обязателен.
- Отмечай breaking changes явно в начале описания.
