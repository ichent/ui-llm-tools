# Skill: commit

## Когда использовать
Когда разработчик просит создать коммит, «закоммить изменения» или подготовить
сообщение коммита.

## Формат сообщения
```
<type>(<scope>): <subject> [<TICKET>]

<body — опционально, что и зачем>
```

- **type**: `feat`, `fix`, `refactor`, `docs`, `test`, `chore`, `style`, `perf`.
- **scope**: затронутая область (например, `ui-kit`, `auth`, `cart`). Опционально.
- **subject**: в повелительном наклонении, без точки в конце, до ~72 символов.
- **TICKET**: номер задачи. Извлекается из имени git-ветки
  (например `feature/ABC-123-...` → `ABC-123`). Если не найден — спросить у разработчика.

## Шаги
1. Посмотри изменения: `git status` и `git diff --staged` (если ничего не
   застейджено — `git diff`).
2. Определи `type` и `scope` по характеру изменений.
3. Извлеки номер тикета из имени текущей ветки: `git rev-parse --abbrev-ref HEAD`.
4. Сформируй сообщение по формату выше.
5. Покажи сообщение разработчику и создай коммит через HEREDOC.

## Пример
Ветка: `feature/ABC-451-add-dark-mode`, изменения в теме `ui-kit`:
```
feat(ui-kit): add dark mode toggle to theme provider [ABC-451]
```
